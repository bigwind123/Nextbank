# Elasticsearch AIOps：受技能範圍限制的操作助理

**案例類型：真實工程專案的公開化說明。**主機、索引、文件內容與查詢結果均以合成資料代替。原始應用整合多種工具；本公開示範只涵蓋唯讀 Elasticsearch 路徑。

## 問題

維運人員用自然語言提出問題時，系統必須將提問連到相關操作知識和資料來源，同時避免把工具回傳誤當成已完成診斷。技能可提供領域指引，也能限制模型看見的工具清單；然而，介面上限制選單本身不等於完整的執行授權。

## 來源系統的流程

聊天室會依目前技能組出提供給模型的工具清單。使用者的問題和工具描述送交各自設定的模型端點；模型若選擇 Elasticsearch 工具，應用以 JSON-RPC MCP 呼叫工具服務，整理結果後再回到對話。Gateway 管理服務不代理這段推論流量。

來源程式的技能工具清單來自設定；在部分舊路徑中，若設定缺漏會退回完整工具清單，而且底層工具 dispatch 沒有持有技能授權上下文。因此，技能範圍的模型可見工具清單不代表執行層已完整封鎖所有其他工具。Elasticsearch 的查詢指引也有一部分依賴模型遵守工具說明與系統指示，不能描述成全面的查詢授權機制。

## 公開示範中的安全改良

本作品集的 Python sample 對上述缺口採取更嚴格的預設：未知技能直接拒絕；每次 dispatch 都重新依所選技能檢查工具是否在允許清單中。這項 fail-closed 驗證屬於重新建構的公開 sample 改良，不是原應用既有能力的描述。

互動 walkthrough 和 Python sample 僅展示合成 Elasticsearch 查詢結果及唯讀工具。真實聊天室有其他可能變更狀態的整合工具，因此不能把此公開子集誤認為完整產品的工具範圍。

## Elasticsearch 查詢界線

- 業務資料查詢和系統指標查詢使用不同查詢方式；工具說明會引導模型選用相應查詢工具。
- 避免不必要的萬用字元查詢，系統指標查詢遵循受限的查詢範本。
- MCP 回應是觀察資料，不是自動化變更。關鍵結論需由操作人員核實時間窗、主機、索引及資料完整性。
- 合成 walkthrough 只呈現固定搜尋回應與可展開的 MCP 工具呼叫紀錄，用來說明回覆和工具細節的範圍；它不驗證來源服務的即時授權狀態。

更完整的公開流程見[Elasticsearch MCP 圖](../assets/diagrams/elasticsearch-mcp.html)。

## 限制

展示的工具選擇、查詢和答案均為合成流程，不包含真實主機名稱、索引、日誌或業務資料。此案例不宣稱模型診斷正確率、事件處理時間改善或自動修復能力。聊天室可呼叫哪些工具仍取決於部署設定和工具服務授權。
